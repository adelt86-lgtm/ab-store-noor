## 1) صيغة الأسعار

**المشكلة:** تظهر الأسعار هكذا: `2.500 دج` و`4.200` و`3.000 دج` (الصور: الطلبات، الواتساب).

**لماذا تهم:** في الجزائر لا تُعد النقطة فاصل آلاف مألوفاً. كثيرون يقرؤون `2.500` على أنها 2.5 دينار، وهذا يهدد الثقة والمبيعات ويسبب نزاعات عند التسليم.

**التصميم المقترح:**
- اعرض الأسعار بأرقام لاتينية، وفاصل آلاف بمسافة رفيعة، وبدون كسور: `2 500 دج`.
- وحّد الدالة في كل مكان: لوحة التحكم، رسالة الواتساب، الطباعة، المتجر العام.
- في الأرقام الكبيرة (الإجمالي) ضع `دج` بخط أصغر وبجانب الرقم.

```ts
// src/lib/format.ts
export function formatMoney(n: number): string {
  return Math.round(Number(n) || 0)
    .toString()
    .replace(/\B(?=(\d{3})+(?!\d))/g, "\u202F"); // مسافة رفيعة غير قابلة للكسر
}
// الاستعمال: `${formatMoney(o.total_price)} دج`
```

## 2) التباين وقابلية القراءة

**المشكلة (الصورتان 2 و3):**
- بانر "✨ مفعّل Pro" نص فاتح جداً على خلفية خضراء فاتحة، يكاد لا يُقرأ.
- بطاقة "حالة الشحنة": نص رمادي على خلفية رمادية داكنة، وبطاقة التتبع بتدرج أخضر رمادي باهت.
- رابط "إدارة المنتجات" بلون باهت كأنه معطّل.

**لماذا تهم:** التاجر يستعمل الهاتف غالباً في الخارج وتحت الشمس. التباين الضعيف يعني نصاً غير مقروء.

**التصميم المقترح:**
- معيار ثابت: نسبة تباين **4.5:1 على الأقل** للنص العادي، و**3:1** للنص الكبير (WCAG AA). افحصها بأداة مثل WebAIM Contrast Checker.
- لا تضع نصاً على تدرج؛ استعمل خلفية موحّدة ونصاً داكناً أو أبيض حسب الخلفية.
- الحالات (قيد التوصيل، تم التسليم، مرتجع) تُعرض كـ **شارة بلون + نص**، لا بلون وحده.

```css
/* بانر Pro */
.pro-banner { background:#ECFDF5; border:1px solid #6EE7B7; color:#064E3B; }
.pro-banner strong { color:#065F46; }

/* بطاقة حالة الشحنة: فاتحة بدل الرمادي الداكن */
.shipment-card { background:#FFFFFF; border:1px solid #E5E7EB; color:#111827; }
.shipment-card .label { color:#4B5563; }   /* ثانوي لكن مقروء */
.shipment-card .value { color:#111827; font-weight:600; }

/* روابط ثانوية: لا تقل عن هذا */
.link-muted { color:#4B5563; }
```

|--------|-----------------|
| جديد | خلفية `#DBEAFE` نص `#1E3A8A` |
| مؤكد | خلفية `#E0E7FF` نص `#312E81` |
| قيد التوصيل | خلفية `#FEF3C7` نص `#78350F` |

| ملغى/مرتجع | خلفية `#FEE2E2` نص `#7F1D1D` |

## 3) النص الافتراضي في المتجر العام

**المشكلة (الصورة 1):** يظهر للزبون "مرحباً بك في متجرك. عدّل المنتجات والنصوص من لوحة التحكم." وهو نص قالب موجّه للتاجر.

**لماذا تهم:** يعطي انطباع متجر غير مكتمل، فيغادر الزبون.

**التصميم المقترح:**
- إن كان النص مساوياً للافتراضي، **لا يُعرض** في المتجر العام.
- في لوحة التاجر أضف بطاقة **"أكمل متجرك"** بقائمة خطوات:
  1. ارفع شعار المتجر
  2. عدّل عنوان الواجهة ووصفها
  3. أضف 3 منتجات على الأقل
  4. أضف رقم واتساب حقيقي
  5. اضغط "نشر المتجر"
- لا يُسمح بالنشر العام حتى تكتمل الخطوات 2 و3 و4 (أو تحذير واضح عند تخطيها).

```ts
const DEFAULT_HERO = "عدّل المنتجات والنصوص من لوحة التحكم.";
const showHeroText = heroDescription && heroDescription.trim() !== DEFAULT_HERO;
```

## 4) الشاشة الأولى في المتجر العام

**المشكلة (الصورة 1):** أول شاشة في الهاتف: شريط إعلان + ترويسة + شارة + عنوان ضخم + وصف + زر "اكتشف المنتجات". لا منتج ولا سعر ظاهر قبل التمرير. وشارة "حصرياً" واسم المتجر والـslug (`/adelt86`) تتكرر مرتين، وشارة "حصرياً" تغطي صورة المنتج.

**لماذا تهم:** زبون الفيسبوك/تيك توك يريد رؤية المنتج والسعر فوراً.

**التصميم المقترح (ترتيب الشاشة الأولى):**

```
┌───────────────────────────┐
│ شريط إعلان (سطر واحد)      │
│ ☰   اسم المتجر      🛒(0) │  ← ترويسة واحدة فقط (بدون slug)
├───────────────────────────┤
│ غلاف مضغوط (ارتفاع ≤ 160px)│  ← عنوان قصير + زر "تسوّق"
├───────────────────────────┤
│ [ صورة المنتج 1 ]          │
│ اسم المنتج · 2 500 دج      │  ← يظهر المنتج والسعر دون تمرير
│ [ اطلب الآن ]              │
└───────────────────────────┘
```

- احذف الشارة والـslug المكررين من مكان الغلاف؛ يبقى الاسم في الترويسة فقط.
- الشارات ("حصرياً"، "جديد") تُوضع **أعلى زاوية الصورة بحجم صغير** ولا تغطي مركز المنتج.
- زر السلة العائم: اتركه، لكن ثبّته أسفل الشاشة (ضمن منطقة الإبهام) وبحجم لا يقل عن 48×48px.
- **صور الموردين:** كثير من التجار سيرفعون صور موردين بنص إنجليزي أو شعارات. ضع إرشاداً في رفع الصور: مربعة 1:1، خلفية نظيفة، 1000px.

## 5) أزرار الأيقونات والحذف

**المشكلة (الصورة 2):** صف أيقونات بلا نص: واتساب، شاحنة، نسخ، طباعة، حذف، "+". زر الحذف بجانب "+" مباشرة.

**لماذا تهم:** تاجر جديد لا يعرف معنى الشاحنة أو "+"، وضغطة خاطئة على الحذف تخسره طلباً.

**التصميم المقترح:**
- الأزرار الأساسية بأيقونة **ونص**: `تأكيد عبر واتساب` · `شحن` · `طباعة`.
- الأزرار الثانوية (نسخ، "+") داخل قائمة "⋯ المزيد".
- **الحذف** بلون أحمر داخل قائمة "المزيد" فقط، ويفتح نافذة تأكيد: "حذف الطلب نهائياً؟ لا يمكن التراجع" مع زر **إلغاء** هو الافتراضي.
- حجم أي زر لمس ≥ **44×44px**، مع `aria-label` على كل أيقونة.
- تباعد ≥ 8px بين الأزرار.

## 6) مفاتيح التبديل (قنوات التواصل)

**المشكلة (الصورة 4):** كل المفاتيح (Facebook, Instagram, Telegram, TikTok) بنفس الشكل: دائرة بيضاء على اليسار وخلفية بنفسجية. لا يُعرف أيها مفعّل.

**التصميم المقترح:**
- **مفعّل:** خلفية خضراء/لون العلامة + علامة ✓ + نص "مفعّل".
- **متوقف:** خلفية رمادية `#D1D5DB` + نص "متوقف".
- الحالة لا تعتمد على اللون وحده (نص أو أيقونة).
- حقل الرابط يظهر **فقط عند التفعيل**، ويُخفى عند الإيقاف.

## 7) اتجاه الحقول وتحقق الروابط

**المشكلة (الصورة 4):** النص الإرشادي يظهر مقلوباً: `…/https://facebook.com`، بسبب RTL.
ومن الكود: روابط التواصل تُوضع في `href` بلا أي تحقق (خطر `javascript:`).

**التصميم المقترح:**
- كل حقول الروابط والبريد والأرقام: `dir="ltr"` مع `text-align: left`.
- تحقق قبل الحفظ **وعند العرض**: `https://` فقط، والنطاق مطابق للمنصة.
- رسالة خطأ واضحة تحت الحقل: "الرابط يجب أن يبدأ بـ https://facebook.com".

```ts
const SOCIAL_HOSTS: Record<string, string[]> = {
  Facebook:  ["facebook.com", "www.facebook.com", "fb.com", "m.facebook.com"],
  Instagram: ["instagram.com", "www.instagram.com"],
  Telegram:  ["t.me", "telegram.me"],
  TikTok:    ["tiktok.com", "www.tiktok.com"],
};

export function safeSocialUrl(platform: string, raw: string): string | null {
  try {
    const u = new URL(raw.trim());
    if (u.protocol !== "https:") return null;
    return (SOCIAL_HOSTS[platform] || []).includes(u.hostname) ? u.toString() : null;
  } catch { return null; }
}
// عند العرض: const href = safeSocialUrl(platform, socialLinks[platform]);  إن كان null لا تعرض الرابط
```

```html
<input type="url" dir="ltr" inputmode="url" placeholder="https://facebook.com/اسم-صفحتك" />
```

## 9) التاريخ والوقت

**المشكلة (الصورة 3):** `2026/10/1، 12:34:47 ص`: ترتيب مقلوب في واجهة عربية، وثواني غير لازمة، و"ص/م" مربكة.

**التصميم المقترح:** صيغة ثابتة بأرقام لاتينية وبدون ثواني: **`01/10/2026 00:34`**.

```ts
export const formatDateTime = (d: string | number | Date) =>
  new Date(d).toLocaleString("fr-FR", {
    day: "2-digit", month: "2-digit", year: "numeric",
    hour: "2-digit", minute: "2-digit",
  }).replace(",", "");
```

## 11) صفحة الهبوط

**المشكلة (الصورتان 2 و5):**
- فراغ أسود كبير (~240px) أعلى الصفحة وفراغات واسعة بين الأقسام.
- خطوط صغيرة جداً داخل المحاكاة (mockup) كأنها بعرض سطح مكتب.
- تصميمان مختلفان: ذهبي/أسود (2) وبرتقالي/أسود (5).
- العنوان "متجرك الإلكتروني بساطة. طلبات. نمو." مفكك لغوياً.

**التصميم المقترح:**
- **اختر تصميماً واحداً** (أنصح بنسخة الصورة 5 لأنها أوضح على الهاتف) واحذف الآخر.
- أعلى الصفحة: لا `min-height` كبير؛ الترويسة ثم الشارة مباشرة.
- تباعد الأقسام: 56–72px على الهاتف.
- المحاكاة: استبدل النص المصغّر بلقطة شاشة حقيقية للوحة التحكم (صورة)، أو كبّر الخط ≥ 14px.
- ترتيب الأقسام: العنوان ← زر البدء ← لقطة ← المشكلة (طلبات وهمية) ← الحل (واتساب) ← الأسعار ← أسئلة شائعة ← زر ختامي.

**بدائل للعنوان:**
1. أنشئ متجرك واستقبل طلباتك على واتساب في دقائق
2. متجرك الإلكتروني جاهز في 5 دقائق — والدفع عند الاستلام
3. بع على الإنترنت بدون برمجة وبدون عمولة

```css
.hero { padding-top: 24px; padding-bottom: 40px; min-height: 0; }
.section { padding-block: 56px; }
.mockup * { font-size: max(14px, 1em); }
```

## 12) صفحة 404

**المشكلة (آخر صورة):** نص إنجليزي فقط ("Page not found" / "Go home") والنقطة في الاتجاه الخاطئ، بينما الموقع عربي/فرنسي.

**التصميم المقترح:**
- عنوان عربي وفرنسي: **"الصفحة غير موجودة · Page introuvable"**.
- نص: "الرابط غير صحيح أو تم نقله."
- زران: **"العودة للرئيسية"** و**"إنشاء متجري"**.
- تأكد أن الصفحة تعيد حالة HTTP **404** حقيقية (لا 200)، حتى لا تفهرسها محركات البحث.

## 13) رابط المتجر

**المشكلة:** رابط المتجر `dzairstore.online/?store=adelt86`: طويل وأقل ثقة وأضعف في الفهرسة والمشاركة. وجميع المتاجر تعيش على نفس أصل لوحة التاجر (خطر أمني: أي XSS في متجر قد يسرق جلسة تاجر).

**التصميم المقترح (بالترتيب):**
1. **الأفضل:** نطاق فرعي لكل متجر `adelt86.dzairstore.online` عبر Wildcard DNS (`*.dzairstore.online`) على Vercel. يفصل الأصول أمنياً ويعطي علامة أفضل.
2. **بديل أسهل:** مسار `/s/adelt86`.
3. في لوحة التاجر: زر "نسخ رابط المتجر" + "مشاركة على واتساب" + رمز QR (موجود في وعودك للمحل).
4. احجز الـslugs التالية: `www, admin, api, app, dashboard, login, auth, support, super-admin`.

## 14) معاينة المشاركة (`og:image`)

**المشكلة:** الصفحة تعلن `twitter:card = summary_large_image` لكن لم تظهر `og:image`. مشاركة الرابط على واتساب/فيسبوك تظهر بلا صورة. والـHTML المرسل للخادم فيه "جاري التحميل…" فقط (الصفحة تُرسم من المتصفح).

**التصميم المقترح:**
- صورة `1200×630` بصيغة PNG/JPG (أقل من 300KB): الشعار + العنوان + لقطة المنتج.
- ضع الوسوم في `<head>` الصفحة الرئيسية، وتأكد أنها في الـHTML المرسل (SSR/prerender).
- لكل متجر: `og:image` = صورة أول منتج أو الشعار، و`og:title` = اسم المتجر.

```html
<link rel="canonical" href="https://www.dzairstore.online/" />
<meta property="og:image" content="https://www.dzairstore.online/og-cover.png" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta property="og:locale" content="ar_DZ" />
<meta name="twitter:image" content="https://www.dzairstore.online/og-cover.png" />
```

# الجزء الثاني: `robots.txt` و`sitemap.xml`

## الهدف
- السماح لمحركات البحث بفهرسة صفحة الهبوط والمتاجر المنشورة.
- منع لوحة التاجر ولوحة الإدارة وصفحات الدخول والـAPI.
- خريطة موقع تتحدث تلقائياً عند نشر متجر جديد.

## قرار أولاً: النطاق الرئيسي
اختر **واحداً**: `www.dzairstore.online` أو `dzairstore.online` (بدون www). فعّل في Vercel تحويلاً 301 من الآخر إليه. (في لقطتك ظهر النطاق بدون www بينما الملفات مكتوبة على www.) إن اخترت بدون www، غيّر `SITE` في `api/sitemap.ts` وسطر `Sitemap:` أدناه.

## `public/robots.txt`

```txt
User-agent: *
Allow: /
Disallow: /dashboard
Disallow: /super-admin
Disallow: /auth
Disallow: /api/
Disallow: /*&product=

Sitemap: https://www.dzairstore.online/sitemap.xml
```

**نسخة احتياطية** إن اضطررت لاستعمال `/api/sitemap` مباشرة (إن فشل الـrewrite):

```txt
User-agent: *
Allow: /api/sitemap
Allow: /
Disallow: /dashboard
Disallow: /super-admin
Disallow: /auth
Disallow: /api/
Disallow: /*&product=

Sitemap: https://www.dzairstore.online/api/sitemap
```

> ملاحظة: `robots.txt` يمنع الزحف فقط ولا يمنع الفهرسة إن وُجدت روابط خارجية. لذلك أضفنا ترويسة `noindex` (أدناه).

## `api/sitemap.ts` (خريطة ديناميكية)

```ts
import type { VercelRequest, VercelResponse } from "@vercel/node";
import { createClient } from "@supabase/supabase-js";

const SITE = "https://www.dzairstore.online";
const esc = (s: string) =>
  s.replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;").replace(/"/g, "&quot;");

export default async function handler(_req: VercelRequest, res: VercelResponse) {
  const urls: { loc: string; lastmod?: string; priority: string }[] = [
    { loc: `${SITE}/`, priority: "1.0" },
  ];

  try {
    const url = process.env.SUPABASE_URL || process.env.VITE_SUPABASE_URL;
    const key = process.env.SUPABASE_ANON_KEY || process.env.VITE_SUPABASE_ANON_KEY;
    if (url && key) {
      const { data } = await createClient(url, key)
        .from("stores")
        .select("slug,created_at")
        .eq("is_published", true)
        .order("created_at", { ascending: false })
        .limit(5000);
      for (const s of data || []) {
        if (typeof s.slug === "string" && /^[a-z0-9][a-z0-9-]{0,60}$/.test(s.slug)) {
          urls.push({
            loc: `${SITE}/?store=${encodeURIComponent(s.slug)}`,
            lastmod: s.created_at ? new Date(s.created_at).toISOString().slice(0, 10) : undefined,
            priority: "0.6",
          });
        }
      }
    }
  } catch {
    console.error("[sitemap] store list failed");
  }

  const body =
    `<?xml version="1.0" encoding="UTF-8"?>\n` +
    `<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">\n` +
    urls
      .map(
        (u) =>
          `  <url><loc>${esc(u.loc)}</loc>` +
          (u.lastmod ? `<lastmod>${u.lastmod}</lastmod>` : "") +
          `<priority>${u.priority}</priority></url>`,
      )
      .join("\n") +
    `\n</urlset>\n`;

  res.setHeader("Content-Type", "application/xml; charset=utf-8");
  res.setHeader("Cache-Control", "public, s-maxage=3600, stale-while-revalidate=86400");
  return res.status(200).send(body);
}
```

(ادمجه مع ترويسات الأمان الموجودة في `vercel.json` ولا تستبدل الملف إن كان لديك تعديلات.)

## خطوات النشر والتحقق
1. ضع الملفات في أماكنها وانشر.
2. افتح `/api/sitemap` مباشرة؛ يجب أن يظهر XML فيه الصفحة الرئيسية ومتجرك المنشور.
3. افتح `/sitemap.xml`؛ إن ظهر 404 من التطبيق (حدث معك) فالـrewrite لم يُطبَّق بعد: تأكد أن `vercel.json` في جذر المشروع وأُعيد النشر، أو استعمل النسخة الاحتياطية من `robots.txt` أعلاه.
4. افتح `/robots.txt` وتأكد من النص.
5. سجّل النطاق في **Google Search Console** وأرسل الخريطة (Sitemaps → أضف الرابط).
6. تحقق من أن `/dashboard` تعيد ترويسة `X-Robots-Tag: noindex` (من أدوات المطور ← Network).

## ما لن يحلّه الـsitemap وحده
- الصفحة تُرسم من المتصفح (`جاري التحميل…` في HTML الأولي). لظهور جيد في البحث ولمعاينات المشاركة، فعّل **SSR أو prerender** على الأقل لصفحة الهبوط وصفحات المتاجر.
- روابط المتاجر `?store=` تُفهرس بصعوبة؛ نطاق فرعي أو `/s/slug` يحسّن ذلك (انظر البند 13).
